# The FLOX Entertainment — Full Website & Corporate Workspace

Полноценная full-stack кодовая база TFE: публичный корпоративный сайт + закрытая рабочая зона с серверной авторизацией, PostgreSQL и API.

## Что реализовано

### Публичная часть
- Главная страница в утверждённом Premium Corporate / dark-only / monochrome стиле.
- Страницы: о компании, каталог проектов, новости, работы и достижения, команда, карьера, партнёры, контакты, пресс-кит, юридическая информация.
- Адаптивная мобильная навигация и макеты.
- Форма обратной связи с сохранением сообщений в PostgreSQL.
- Публичные проекты, новости, достижения, вакансии и партнёры загружаются из API.

### Закрытая часть
- Вход сотрудников по email и паролю; самостоятельная регистрация отсутствует.
- Аккаунты сотрудников создаёт владелец.
- Сессии в HttpOnly cookie, хеширование паролей bcrypt, ограничение частоты входов.
- Ролевая модель и отдельные permission codes; владелец имеет защищённый флаг `is_owner` и обходит обычные роли.
- Рабочая панель, проекты, задачи, команда, сообщения/каналы, календарь, документы, публикации и аудит.
- Загрузка разрешённых типов файлов с лимитом 20 MB.
- Журналирование ключевых действий.

## Технологии
- Node.js 20+
- Express API
- PostgreSQL
- HTML / CSS / Vanilla JavaScript

## Локальный запуск

1. Установите Node.js 20+ и PostgreSQL.
2. Создайте базу данных и пользователя PostgreSQL.
3. Скопируйте `.env.example` в `.env` и укажите `DATABASE_URL`.
4. Сгенерируйте секрет: `openssl rand -base64 48`; вставьте его в `JWT_SECRET`.
5. Установите зависимости: `npm install`.
6. Создайте таблицы: `npm run db:init`.
7. Создайте владельца (пароль минимум 12 символов):
   `npm run owner:create -- owner@example.com "TFE Owner" "Use-A-Long-Unique-Password"`
8. Запустите: `npm start`.
9. Откройте `http://localhost:3000`.

## Развёртывание
Нужен хостинг, который поддерживает Node.js-приложения, и отдельная PostgreSQL-база (например, VPS или PaaS). На production:
- `NODE_ENV=production`
- `COOKIE_SECURE=true` и обязательно HTTPS
- сильный уникальный `JWT_SECRET`
- корректный `DATABASE_URL` и SSL для PostgreSQL, если требует провайдер
- постоянный диск или объектное хранилище для `uploads/`
- резервное копирование базы и файлов
- настроить домен, TLS и ограничения доступа к панели хостинга

GitHub Pages не подходит для запуска этой версии: он публикует статические файлы, но не запускает Node.js API и PostgreSQL.

## Важные замечания перед публичным production-запуском

Это полноценная исходная реализация, но её нельзя считать прошедшей внешний аудит безопасности или готовой к обработке реальных корпоративных данных без настройки окружения и тестирования. Перед запуском необходимо:
- настроить HTTPS, секреты, резервные копии, мониторинг и почтовый канал восстановления доступа;
- проверить и дополнить матрицу прав под реальные должности TFE;
- добавить полноценное управление участниками каналов, реакции, поиск и редактирование/удаление сообщений;
- добавить версионирование документов, workflow согласования, расширенную медиатеку и календарные представления;
- добавить CSRF-защиту для cookie-auth при подключении сторонних доменов, политику CSP и сканирование загружаемых файлов;
- подготовить юридические документы и тексты согласий с юристом.

Не загружайте `.env`, пароли или реальные пользовательские данные в GitHub.
